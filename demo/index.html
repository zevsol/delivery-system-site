02 / Planned Work Item

Planned Work Item · not a created Issue

A Work Item is a structured planned delivery result. The planned create_issue operation records intent; it does not mean GitHub executed it. One Work Item usually maps to one planned Issue, and is not a remote Issue itself.

ONE RECORDED WORK ITEM

Build a responsive personal portfolio website

Outcome

An independent developer needs a portfolio that is easy to browse on desktop and mobile, introduces them, showcases projects, and provides a way to get in touch. Deliver a mostly static personal portfolio with an introduction, project showcase, and contact information, with clear project links and basic keyboard accessibility.

Scope6
  • Show a personal introduction.
  • Show project content with clearly distinguishable links.
  • Provide contact information.
  • Support desktop and mobile layouts.
  • Use mostly static content.
  • Support basic keyboard access.
Non-goals3
  • User login or account management.
  • Payments or subscriptions.
  • An admin panel.
Acceptance Criteria5
  • [ ] The page includes an introduction, project showcase, and contact information.
  • [ ] The page is readable and usable on desktop and mobile viewports without horizontal overflow.
  • [ ] Project links have clear, distinguishable text that identifies their destinations.
  • [ ] Primary project links and contact entry points are keyboard accessible and show visible focus.
  • [ ] The site is mostly static and has no login, payment, or admin features.
Verification4
  • Check layout, readability, and horizontal overflow at desktop and narrow mobile widths.
  • Use a keyboard to reach primary project links and contact entry points, and confirm focus is visible.
  • Check that project link names are clear and distinguishable.
  • Confirm that no login, payment, or admin feature was introduced.
