一个真实的 DS LITE 案例

需求在每一步
变得更清晰。

同一个作品集需求，依次经过三个阶段：人的意图、封存的概念预览，以及展示为 Issue Markdown 的草稿。

01

需求意图

开发者希望制作一个响应式作品集，包含个人介绍、项目、联系方式和键盘访问能力，同时明确排除哪些范围。

收到需求
02

封存预览

本地规划流程返回一个概念级工作项，明确列出范围、非目标、验收标准和验证步骤。没有声明目标仓库。

预览已封存
03

GitHub Issue Markdown

记录中的工作项被呈现为 Markdown 草稿，供人审阅、复制或下载。此步骤不会创建 Issue。

草稿已就绪
交互式过程演示01 / 03

清晰的需求

用开发者自己的语言描述目标和边界。

需求概述

我要开发一个个人作品集网站，支持桌面和移动端，包含个人介绍、项目展示和联系方式。网站以静态内容为主，不需要登录、支付或后台管理。要求基本键盘可访问性和清晰的项目链接。

响应式支持键盘访问静态内容
